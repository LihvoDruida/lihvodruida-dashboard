## Збереження даних, прав і поведінки

- Склад гільдії й опубліковані рейди/пули залишаються публічними для читання.
  Приватні чернетки не відкриваються гостям. Публічність не надає прав мутації.
- Серверний відбір минулих рейдів враховує статус публікації. Чернетка не стає
  публічною лише через минулу дату. Для деталей окремо враховано право бачити
  склад, а індивідуальний ilvl і маркери пріоритету лави залишаються менеджерам.
- У заявках перевірка права перегляду виконується до читання черги; контактні
  поля прибирає чинний sanitizeApplicationsForMentorViewer до передачі в view.
  Новий тест використовує справжній sanitizer, а не його копію.
- Збережено всі поля кандидатів: трекінг, джерело, доступність, дозволені
  контакти, класи/спеки, рейтинги поточного й попереднього сезонів, рейдовий
  прогрес, delivery/recovery, рішення, масова обробка та перехід до наступної заявки.
- Бейдж заявки тепер читає стан тієї самої клієнтської черги, що й дії:
  підтверджене рішення не співіснує зі старим server-rendered «На розгляді».
  Контролери підтвердження, конфліктів, звірки й непевного результату не переписано.
- Збережено debounce пошуку заявок, latest-filter/reset захист, серверний
  пошук, усі URL-фільтри, saved views, позиції списків та повернення до рядка.
- Склад гільдії зберігає 17 URL-параметрів, шість сортувань, page/size,
  RIO/ilvl діапазони, class/spec/faction, роль, рейди сезону й clear-фільтри.
  Кешований live resource і owner-only ручна синхронізація залишились чинними.
- Усі записи рейдів, статуси 50/50/late/skipped, номери запису, ролі/спеки,
  попередження ilvl, пріоритет лави, паті й повноширинна лава збережені.
  Сайт не отримав нового signup endpoint: участь змінюється через Discord.
- У пулах збережено scheduled/open/paused/closed, повторення, послідовні bulk
  операції, відновлення після непідтвердженої відповіді, зняття непевного вибору
  та відсутність автоматичного повторного POST.
- Рекомендації використовують той самий raidPollUniqueDayRecommendations і
  узгодження днів між пулами. Якщо related polls не прочитано, рекомендації
  блокуються з поясненням; матриця і голоси поточного пулу лишаються доступними.
- Матриця використовує спільний максимум для порівняння часу між днями.
  Голоси, доступні/відсутні учасники та вибрані години залишаються у відображенні.
- DropdownMenu отримав closeOnAction: для асинхронних контролерів disclosure
  не ховає live status і фокус результату під час виконання. Escape/outside
  закриття збережено. Native submit/formAction для рейдових дій збережено.

```text
    polls/poll-workspace.module.css
```

DataCard доповнено titleHref/id/listEntry для нативної навігації та пам’яті
рядків. Інші сторінки продовжують використовувати попередній API без змін.
RaidViews/RaidPollViews залишають сумісні реекспорти для редакторів етапу 4:
повторних копій перенесених server renderers не залишено. Клієнтський live
preview редактора належить наступному етапу й не оголошується мігрованим.

Сервіси й presentation, які імпортують серверну рейдову модель, мають server-only
межу. У браузер списку пулів передається легка модель, без масиву голосів,
Discord ID виборців і приватної діагностики запланованої публікації.

## Дизайн і очищення

- Нові workspace CSS Modules використовують центральні токени без style=,
  хардкодних кольорів або довільних padding/margin/gap.
- Нативні progress замінили відсоткові інлайн-ширини; значення bounded і мають
  доступну текстову назву. Старі динамічні кольори рейтингу замінено спільною
  типографікою зі збереженням самих чисел. 13 кольорів класів WoW перенесено
  з JSX у центральні --c-wow-* токени без зміни вихідної палітри.
- Списки й фільтри переносяться за доступною шириною, таблиця складу переходить
  до підписаних рядків у вузькому контейнері, довгі імена/рейди не обрізаються.
- Помилка читання показується окремо від порожнього результату. При помилці
  лічильники не видають нуль за підтверджену кількість записів.
- Прибрано 443 невикористані глобальні правила й 221 підтверджену class-назву
  зі старих namespace. Додатково прибрано незадіяні правила нових CSS Modules.
- Видалено старий GuildRoster.module.css і спорожнілий styles/applications.css,
  його import у layout також прибрано. Список: CSS_CLEANUP_STEP3.json.
- Зоряний/відеофон, навігаційні механіки, assets, SQL-схема, .env і залежності
  не змінювались. Живі профілі, рейди, пули, голоси й групи не видалялись.

## Перевірки та межі

check:community-workspaces входить у verify і build:ci: 19 сценаріїв на
реальних server loaders, sanitizer, рейдових/пулових алгоритмах і React SSR.
Provider boundaries контрольовані; ця перевірка не звертається до production.
Існуючі route/navigation тести виконують справжній route→service→view ланцюжок.
Статичні інваріанти читають фактичні імпорти й реекспорти замість вимагати
повернення старої монолітної розмітки.

Політики API і 124 route.ts-файли не змінювались; остаточне право кожної
мутації й надалі перевіряється endpoint-ом. Production .env не передавався.

Browser fixture production-компонентів зібрано; запуск Chromium заблоковано
socket(): Operation not permitted. Візуальний аудит, перевірка всіх viewport
і клавіатурних взаємодій у браузері не позначені PASS. Реальні OAuth/Discord,
production PostgreSQL і розгортання на VPS не виконувались.

Підсумковий протокол і логи: validation/step3/VALIDATION.md.
Повний код змінених runtime-файлів: PAGE_COMMUNITY_SOURCE.md та дерево src/.

npm ci і npm run build:ci у dashboard/. SQL-міграція та зміна production .env
