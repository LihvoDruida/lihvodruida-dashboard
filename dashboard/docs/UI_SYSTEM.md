# Спільна система інтерфейсу — 3.8.66

## Порядок каскаду

`cascade.css` імпортується першим та визначає порядок: `theme → reset → defaults → components → layout → pages → accessibility`.

- `theme`: токени й параметри ПК/мобільного режиму.
- `reset`: нормалізація браузерних стилів.
- `defaults`: сумісність із доменними назвами старих компонентів. Правила за суфіксами мають нульову специфічність і нижчий пріоритет за явні компоненти та сторінки.
- `components`: спільні поверхні, кнопки, форми, піднавігація.
- `layout`: каркас сторінки й загальна композиція.
- `pages`: внутрішня композиція конкретного екрана, включно з CSS Modules.
- `accessibility`: фокус, сенсорні розміри, reduced motion, forced colors.

Нові компоненти використовують явні спільні класи або власний CSS Module. Не додавати нові глобальні правила за фрагментами назв класів. Псевдоелементи пишуться після `:where()`, наприклад `:where(.card)::after`.

## Каркас і поверхні

Робоча сторінка: `container app-page`; основний потік: `dashboard-shell content-shell app-page-stack`. Загальні розміри: `--page-max`, `--page-gutter`, `--page-gap`, `--panel-padding`, `--card-radius`.

`PageIntro` використовує `hero panel hero--single`, тому текстовий заголовок не отримує порожню другу колонку. Заголовок із діями може використовувати звичайний двоколонковий hero.

`desktop.css` змінює лише токени та не перевизначає композицію карток або таблиць. Доменні сітки лишаються власністю відповідного компонента.

## Контролі

Звичайні дії: `.btn` із `.primary`, `.subtle`, `.secondary`, `.ghost`, `.danger`, `.warning`, `.success`; компактні — `.btn-sm`, іконкові — `.btn-icon`.

Висота й оформлення походять із `--control-height`, `--control-height-sm`, `--control-font-size`, `--control-radius`, `--control-border`. У CSS Modules спільну кнопку вибирати через `:global(.btn)`.

Спеціалізовані контроли можуть мати свою композицію; вони мають бути явно класифіковані в `audit-ui.cjs`.

## Адаптація

- Каркас і навігація перемикаються на 1000/1001 px.
- До 640 px таби допускають горизонтальне прокручування; дії форм переносяться й розтягуються.
- На сенсорних пристроях спільні кнопки мають мінімальні розміри 44 px, включно з компактними варіантами.
- На вузьких екранах поля вводу мають шрифт щонайменше 16 px; довгі назви й кнопки переносяться.
- Шапка та меню враховують безпечні області екрана.
- Hover діє лише за `(hover: hover) and (pointer: fine)`.
- Таблиці використовують внутрішнє прокручування або карткову композицію. Не приховувати переповнення всієї сторінки для маскування помилки.

## Контроль якості

`audit:styles` перевіряє структуру CSS та консервативно визначає невикористані селектори, токени й анімації. `check:style-system` перевіряє CSS-шари, імпорти, сенсорні параметри, hover, псевдоелементи та ізоляцію desktop. `audit:ui` перевіряє каркас сторінок і класифікацію контролів.

Перевірки входять до `verify` та `build:ci`. Візуальні результати й обмеження наведено в `docs/RELEASE_3.8.66.md` у корені проєкту.
