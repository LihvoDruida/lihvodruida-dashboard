# Dashboard 3.15.0 — платформи учасника, помилки й журнал

18 жовтня 2026 року. Сумісний із Site 4.6.1.

## Керування

Сторінка `/dashboard/streamers` доступна лише власнику сервера й адміністратору. Та сама перевірка активної сесії виконується в API перед будь-яким читанням налаштувань або зміною. Модератор і звичайний учасник керування не отримують.

Натисни «Додати учасника», введи Discord ID один раз, додай Twitch, YouTube та/або TikTok кнопками платформ і натисни «Зберегти учасника». Для кожної платформи окремо налаштовуються активність, LIVE на сайті та повідомлення про ефір або відео. TikTok має лише відеосповіщення з дозволом автора; автоматичний LIVE не підтримується використаним Display API.

Для чинного учасника використай «Керувати платформами». Discord ID залишається тим самим. Можна додати платформу, відредагувати канал або прибрати платформу з форми; видалення набирає чинності після збереження та підтвердження. «Видалити учасника» прибирає всі його платформи з моніторингу після підтвердження. Учасника з Discord ця дія не видаляє.

Існуючі записи автоматично групуються за Discord ID. Їхні ID каналів, історія, токени та стан зберігаються; повторне додавання не потрібне. Чинні кілька каналів однієї платформи також залишаються видимими й доступними для редагування. Загальний ліміт — 30 каналів, YouTube — до 5.

## Збереження й синхронізація

Усі зміни платформ одного учасника зберігаються однією PostgreSQL-транзакцією. Некоректний канал, дублікат, перевищення ліміту чи відмова перевірки платформи не залишають частково збережений набір. Ревізії всіх платформ учасника захищають від перезаписування паралельним редактором. Незмінена платформа зберігає свою ревізію, стан і прив’язку очікуваних сповіщень.

Виправлено обхід ліміту YouTube через зміну платформи вже наявного каналу. Унікальність перевіряється також за канонічним ID провайдера; @handles порівнюються без урахування регістру. Авторизація TikTok зберігається при редагуванні з порожніми полями токенів і повторному ввімкненні того самого каналу.

Результати й журнал оновлюються у фоні кожні 20 секунд, коли вкладка видима. Відкрита форма учасника та незбережені перемикачі глобальних налаштувань не скидаються. Зовнішню зміну ревізії видно як конфлікт; збереження застарілої форми блокується до повторного відкриття актуальних даних.

## Помилки та журнал

Замість сирих кодів показуються зрозуміла причина, дія для усунення та позначення проблемної платформи/поля. Відокремлено відсутні ключі, відмову авторизації, квоту платформи, таймаут, некоректну відповідь, відсутнього учасника, права Discord і проблеми сховища. Для YouTube HTTP 403 quotaExceeded більше не маскується як неправильний ключ.

Помилка відповіді API повертає безпечні `code`, `error`, `hint`, HTTP-статус, поле та код звернення для зіставлення з журналом. Тіла сторонніх помилок і секрети не передаються в інтерфейс. HTML замість JSON, відсутність мережі й таймаут обробляються без втрати форми. Після невизначеного результату надсилання запропоновано оновити список перед повтором. Відмова журналювання після успішного запису не перетворюється на хибне повідомлення «зміни не збережено».

Картка платформи окремо показує останню успішну перевірку, останню спробу й запланований повтор. Перша невдала перевірка має власний час і більше не виглядає як повна відсутність спроб. Вимкнену перевірку не можна вручну запускати як успішну дію.

Діагностика записується в чинний PostgreSQL `system_logs` із `resource_type=guild-streamer`, платформою, етапом і безпечним кодом. Використовується чинна система зберігання та очищення журналів, без окремої паралельної бази. На сторінці показано останні 30 записів за 72 години та фільтр помилок/попереджень. Незмінна помилка перевірки не створює запис на кожному циклі; успішне відновлення або інша проблема створюють новий запис. Окремо показана черга Discord, причина затримки, число невдалих спроб та час наступної спроби.

Логування не надсилає діагностику в Discord: записи мають категорії integration/discord, а не security. Налаштовані сповіщення про ефіри й відео працюють через чинну чергу публікацій із захистом від дублювання.

## Оновлення

Оновити файли повного стека з архіву, зберігши чинні env-файли й дані. З кореня стека Dashboard, де `docker-compose.yml`:

```bash
make rebuild-dashboard
```

Для переходу з версії до 3.14.0 використовуй `make up`, щоб завантажити також фоновий розклад стрімерів. Окрема міграція даних не потрібна: використовується чинна схема documents/system_logs. Потрібні ключі платформ зберігаються у `dashboard/.env.production`; налаштування платформ описані в `GUILD_STREAMERS_2026-10-18_UA.md`.

Публічний контракт стрімерів не змінювався, тому наявний Site 4.6.1 сумісний. Виправлення приватного маршруту з Dashboard 3.14.1 збережено.

## Перевірка

30 сценаріїв `check:streamers` виконують справжні модулі PostgreSQL/DocumentStore, захисний proxy, провайдери, журнал і чергу через PGlite з підміненими зовнішніми API. Включено додавання трьох платформ, повний відкат при помилці, збереження ревізії незміненого каналу, паралельні зміни, квоту YouTube, часткове й повне видалення, відмову аудиту після успішного запису та нерозголошення токенів.

Браузерна перевірка виконує фактичні React-компоненти з реальними стилями на 320/390/1440 px: спільна картка, помилки полів, HTML-відмова, фонове оновлення без скидання форми, глобальні налаштування, TikTok, видалення та LIVE-блок сайту. Скриншоти використовувалися лише для внутрішньої візуальної перевірки.

Ключі виробничих платформ, виробничий VPS і надсилання у справжній Discord у цьому середовищі не змінювалися.
