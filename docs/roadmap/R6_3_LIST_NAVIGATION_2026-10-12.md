# R6.3 — збережені перегляди та повернення до запису

Dashboard **3.8.76**; bot **3.6.6**. Дата: 12.10.2026, Europe/Kyiv.

## Результат

У каталогах профілів та заявок запам’ятовуються фільтри. Повернення зі сторінки профілю або власних налаштувань веде до тієї самої сторінки та відкритого рядка. Наприклад, після перегляду учасника на другій сторінці не потрібно знову вводити пошук і проходити сторінки.

Можна зберегти до п’яти іменованих подань. Однакова назва замінює наявне подання. Подання містить лише фільтри, без курсора, даних учасників, контактів або рішень модерації. Нові елементи використовують системні бурштинові кольори та спільні кнопки. Фон, логування й прийняття правил збережені.

У заявках прибрано повторне застосування незмінених фільтрів при відкритті й оновленні результатів. Пошук має затримку 360 мс; клас, статус і сортування застосовуються одразу з актуальним пошуком. Повільна відповідь при скиданні не створює додаткового переходу. Клас із посилання, якого немає серед варіантів, залишається видимим і може бути явно скинутий. Сервер використовує ті самі нормалізовані дозволені фільтри, що й пам’ять подань.

## Відновлення

| Вхід | Поведінка |
|---|---|
| Посилання з параметрами або якорем | Явне посилання має пріоритет |
| Пункт меню без параметрів | Відновлює останній перегляд у цій вкладці |
| «Показати всі» або «Скинути» | Явний `view=all` обходить автоматичне відновлення |
| «Повернутися до списку профілів» | Фільтри, курсор, рядок і його позиція |
| Рядок видалено або відфільтровано | Наступний сусід, потім попередній; інакше доступна позиція прокручування |
| Сервер відхилив курсор | Перша дозволена сторінка; відхилений курсор не залишається останнім переглядом |
| Звичайне оновлення заявок | Не повертає прокручування до старого запису |

Повернення підсвічує відкритий рядок і переводить на нього фокус. Ввід, клік або прокручування користувача скасовують відкладене відновлення. Іменоване подання та відправлення форми фільтрів профілів починають список з початку без попереднього курсора. Посилання повернення не додаються до сценарію прийняття правил.

## Межі та захист

Стан зберігається в `sessionStorage` цієї вкладки на 24 години від останньої активності; позиція має власний строк. Історія обмежена вісьмома адресами, подання — п’ятьма, вхідний JSON — 64 KiB. Це не постійні налаштування облікового запису: закриття вкладки або обмеження браузера може видалити стан.

Ключ містить хеш ідентичності та контексту доступу: роль, група, дозволи, Discord-ролі, owner та impersonation. Зміна облікового запису або доступу не використовує інший контекст. Це ізоляція інтерфейсу; серверні перевірки залишаються обов’язковими. Каталог R3 перевіряє курсор і права до фільтрів та LIMIT. Заявки зберігають обмеження модерації й приховування контактів наставникам.

Відновлюються лише точні локальні маршрути `/profiles` і `/applications` з дозволеними параметрами. Абсолютні URL, інші маршрути, невідомі й приватні параметри відкидаються. Названі подання завжди відкидають курсор. Ідентифікатори рядків кодуються без колізій від видалення символів; якір перевіряється та шукається через `getElementById`.

Пошкоджений стан не перезаписується автоматично; його можна явно очистити. Відмова читання й нестача місця мають окремі повідомлення. Звичайні фільтри працюють без пам’яті. Відновлення позиції обмежене двома animation frames; тривалого опитування DOM немає. Пізні зміни геометрії, наприклад при повільному завантаженні зображень, можуть змістити рядок після відновлення.

## Перевірка та оновлення

Точні результати цього релізу: [R6_3_VALIDATION_2026-10-12.json](R6_3_VALIDATION_2026-10-12.json). Браузер перевіряє реальні React-компоненти з локальними HTTP-фікстурами та підміною навігації Next; це не авторизоване тестування бойового Next.js або Discord.

Для повторення: `npm run check:list-navigation`, `npm run test:profiles` з окремою тестовою PostgreSQL, `npm run lint`, `npm run build:ci` у builder-контексті Dockerfile. Тест PostgreSQL створює приватну схему й видаляє її; бойовий DATABASE_URL не використовується.

Оновити dashboard штатною процедурою. Нової SQL-міграції, cron-задачі чи дії Discord у R6.3 немає. Для відкату повернути dashboard 3.8.75; попередня версія ігнорує нову браузерну пам’ять. VPS та бойову базу цього разу не змінено.

R6 продовжується: контекстні наступні дії, навігація інших великих списків, безпечне перенесення ручних призначень при зміні ID групи, додаткові стани автоматизацій. Повний R6 не заявлено завершеним. Перенесення призначень груп залишається окремою незавершеною задачею.
