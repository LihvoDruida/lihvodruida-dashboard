# R7.4 — підтвердження дій і результати рейд-пулів

Dashboard **3.8.97**, bot **3.6.9**, contract **1.1.1**. База — повний пакет 3.8.96. Перевірено 15.10.2026.

## Відтворені дефекти

Production-компоненти 3.8.96 отримали HTTP 200 з HTML замість відповіді API. Кнопки паузи, перерахунку, видалення та карткового закриття показали успіх і викликали refresh; видалення також виконало перехід до списку. Відсутній ok:true не вважався помилкою. У масовому закритті одна підтверджена відповідь та одна HTML-відповідь дали «Оброблено 2» з успішним toast.

Новий клієнт підтверджує мутацію лише за явним JSON-значенням ok:true в об’єкті. Порожні, некоректні, HTML, null, масиви та неboolean ok не підтверджують дію. Загальний HTTP-клієнт підтримує JSON навіть за неточним Content-Type; перевіряється саме розібраний payload. Транспортні заголовки, same-origin credentials та no-store збережені.

## Результат у формі

Чотири контролери використовують спільний useRaidPollMutation. Кожен запит має дедлайн 45 секунд, retries:0 і request lane. При демонтажі компонента запит скасовується; пізня відповідь не запускає toast, навігацію чи оновлення стану. Скасування браузерного запиту не є доказом зупинки серверної операції.

Постійний атомарний status-регіон показує локальний результат і отримує фокус після дії. Власний перехід користувача до іншого елемента має пріоритет. Для непідтвердженого результату є посилання «Перевірити стан». Непідтверджена мутація не викликає успішний refresh або redirect і не повторюється автоматично. Перевірка за посиланням — явна навігація користувача; нового автоматичного GET-відновлення тут немає.

Пауза всередині картки й сусідні close/delete/sync взаємно блокуються на час запиту. Під час масової дії блокуються також індивідуальні контролери її списку. Компактна кнопка паузи має доступну назву.

У керуванні публікацією, видаленні та bulk підтверджений результат із зауваженням до Discord показує часткове виконання за наявним контрактом API. Зміна запису та перевірка Discord — окремі результати. Перенаправлення standalone-видалення обмежене локальними адресами /polls.

## Масові дії

Операції лишаються послідовними. Для кожного пулу зберігаються назва, результат і пояснення; короткий live-підсумок подано окремо від повного списку.

| Результат | Значення |
|---|---|
| confirmed | API явно підтвердив виконання |
| partial | API підтвердив зміну та повернув зауваження до зовнішнього результату |
| rejected | Явна відмова payload або відомі помилки доступу/валідації |
| unconfirmed | Відсутнє підтвердження, втрачена відповідь, тайм-аут або непевний HTTP-результат |

HTTP 400 у наявних маршрутах може виникнути після часткової зовнішньої дії, а 409 — для незавершеної публікації. Ці коди консервативно віднесено до unconfirmed разом із 408 і 5xx. Результат rejected описує відповідь API, не проводить аудит усіх попередніх операцій над ресурсом.

Непідтверджені та підтверджені елементи прибираються з вибору, щоб наступне натискання масової кнопки не повторило їх випадково. Відхилені лишаються вибраними для свідомої подальшої дії. Посилання ведуть до конкретного пулу; після підтвердженого видалення — до списку замість уже видаленого ресурсу. Вихід зі сторінки припиняє відправлення наступних елементів.

## Перевірки

**18 HTTP-сценаріїв** завантажують справжні raidPollMutation, dashboardApiClient та apiHttp із контрольованим fetch: позитивне підтвердження, шість неправильних JSON-форм, HTML, зламаний/порожній body, явна відмова, HTTP 400/403/408/409/503, мережевий збій, abort, частковий Discord-результат та обмеження redirect. Кожна мутація надсилається один раз.

**15 browser-сценаріїв** використовують production React-компоненти та CSS: чотири HTML-відповіді, поелементний bulk, успішна пауза, дедлайн, взаємне блокування, демонтаж, збереження ручного фокусу, скасування destructive confirmation, bulk-видалення, відхилені елементи та дев’ять ширин 320–1920 px. Для timeout-сценарію браузерний timer 45 секунд прискорено до 80 мс; production-значення не змінене.

```sh
npm run check:poll-mutations
npm run check:poll-actions-browser
npm run build:ci
npm run lint
```

check:poll-mutations включено до verify та build:ci. Browser suite використовує зовнішні Playwright/esbuild/Chromium через MISTBLOSSOM_QA_MODULES та MISTBLOSSOM_QA_CHROMIUM; MISTBLOSSOM_QA_OUTPUT задає каталог звіту. Залежності production image не розширено.

Машинні результати, відтворення попередньої версії та остаточні build/standalone gates: [R7_4_VALIDATION_2026-10-15.json](R7_4_VALIDATION_2026-10-15.json).

## Межі та наступний крок

Це локальна перевірка клієнтських компонентів і HTTP-контракту з контрольованими відповідями. Живі Discord/PostgreSQL, Docker image, фактичний RSC refresh, озвучення NVDA/TalkBack та відновлення після повного перезапуску браузера не перевірялися. Історія результатів цього bulk зберігається у стані компонента, а не в новій серверній таблиці. Повної атомарності між різними вкладками чи різними адміністраторами клієнтські блокування не створюють.

R7.4 завершено в зазначеному обсязі. Далі — інспекція форми й навігації очищення Discord (R7.5), потім решта R7 та вимірювання SQL/API на стенді. Живе приймання R6 залишається за перевіркою користувача. SQL-схема, бот, частота cron та дизайн журналу не змінювалися. Відкат — повний пакет 3.8.96. На VPS цей пакет не встановлено.
