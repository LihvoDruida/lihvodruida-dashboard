# R7.2 — клавіатура, фокус і стан робочих сценаріїв

Dashboard **3.8.94**, bot **3.6.9**, contract **1.1.1**. База — повний пакет 3.8.93. Перевірено 15.10.2026, Europe/Kyiv.

## Відтворення на 3.8.93

Ізольований Chromium запускав реальні компоненти попередньої версії та її components.css. API-відповіді контрольовані; справжніх рішень, публікацій чи видалень не виконували.

| Сценарій | 3.8.93 | 3.8.94 |
|---|---|---|
| Enter на «Прийняти», сервер підтверджує рішення, кнопки зникають | activeElement = BODY | Фокус на результаті цієї заявки |
| Помилка публікації та контрольного читання, дія запису зникає | BODY | Фокус на поясненні непідтвердженого результату |
| Успішний повтор читання нагадувань, кнопка повтору зникає | BODY | Фокус на стані нагадувань усередині діалогу |
| Непідтверджене видалення, кнопка стає недоступною | BODY | Власне повідомлення видалення; наступний Tab веде до «Оновити список» |

| Порожній live-регіон публікації | display:none | Візуально прихований без display:none |

Окремо поліпшено контекст відкриття діалогу: початковий фокус на заголовку, унікальні ID через useId, aria-describedby на інструкцію. Початковий фокус на кнопці закриття сам по собі не заявляється порушенням стандарту; новий варіант краще задає контекст довгої форми.

## Реалізація

Спільний useActionFocus запам’ятовує кнопку конкретної операції. Після завершення він повертає втрачений фокус до доступної кнопки або до результату, якщо кнопку прибрали чи залишили disabled. Результати мають tabIndex=-1: їх можна фокусувати програмно, але вони не додають зайвих зупинок до звичайної Tab-послідовності.

Якщо користувач перевів фокус до іншого елемента або натиснув поза робочим блоком, завершення запиту не перехоплює фокус. Є також перевірка document.hasFocus; обробники прибираються після операції та при демонтажі. Відновлення не запускає додаткового POST, GET або router.refresh.

Заявки отримали іменовану групу та aria-busy, яку також бачить наявний захист глобального live-refresh. Масова обробка має постійний атомарний status із короткими підсумковими числами. Список усіх результатів розташований окремо від live-регіону, щоб не подавати весь список як одне повідомлення. Його звичайні hash-посилання ведуть до focusable результату конкретної заявки. «Наступна заявка» зберігає перехід до доступної основної дії та враховує reduced motion.

Стан публікації, нагадувань і видалення подано постійними status-регіонами. Порожні регіони прибрані з візуального потоку за допомогою clipping; display:none для них не використовується. Фокусовані результати та заголовок діалогу мають видиму рамку. Підтверджене видалення показує завершений стан замість застарілого «Видаляємо…» під час оновлення списку.

## Перевірки

**18/18 нових браузерних сценаріїв**:

- остаточне рішення, непевний результат і явне GET-відновлення без повторного POST;
- непідтверджене видалення та перехід до перевірки списку;
- завершення запиту після переходу користувача до іншого елемента;
- масова обробка, відмова від підтвердження, короткий постійний live-регіон та точні hash-переходи;
- завершення й збій публікації;
- початковий фокус/опис діалогу, повтор читання нагадувань, Escape і повернення до launcher;
- Tab/Shift+Tab без потрапляння до фонових контролів, стрілки радіогрупи;
- reduced motion, видимий фокус, відсутність JS-помилок і переповнення на дев’яти ширинах 320–1920 px.

У Chromium нативний dialog допускає перехід Tab у chrome браузера. Тест відрізняє це від фокусу на фоновому DOM: BODY дозволений лише коли document.hasFocus() === false; повернення в документ знову проходить через модальне вікно.

**15/15 попередніх browser-сценаріїв запису** також пройшли: чернетки, тайм-аути, повтор читання, хибні HTML-відповіді, ручний запис, подвійний submit, скасування, live-refresh та адаптивність.

Повний **build:ci — exit 0**, включно з TypeScript, поведінковими/контрактними наборами, CSS/UI-аудитами, production build та standalone gate. Після останньої зміни guard-а фокусу повторено TypeScript, production build і **6/6** перевірок готового пакета. ESLint усього проєкту та фінальних модулів — exit 0. Попередження dynamic filesystem tracing не повернулися. Фокус і повідомлення заявки оглянуто візуально на 390 px.

Команди з dashboard:

```sh
npm run check:workflow-accessibility-browser
npm run check:raid-attendance-browser
npm run build:ci
npm run lint
```

Браузерні suite потребують Playwright, esbuild і Chromium; їхнє зовнішнє розташування задають MISTBLOSSOM_QA_MODULES, MISTBLOSSOM_QA_CHROMIUM та MISTBLOSSOM_QA_OUTPUT. Chromium не є новою залежністю Docker build. Машинний підсумок: [R7_2_VALIDATION_2026-10-15.json](R7_2_VALIDATION_2026-10-15.json).

## Межі та подальший порядок

Це локальна перевірка реальних React-компонентів, API-клієнта, request lanes і CSS із контрольованим API та адаптером Next navigation. Вона не є перевіркою живого Next RSC-переходу, видалення картки після справжнього server refresh, Discord/VPS, PostgreSQL чи Docker image. NVDA/TalkBack, озвучення повідомлень та фактичне перемикання вкладок/вікон ОС не перевірялися. Семантика DOM і keyboard focus перевірені; повна відповідність WCAG не заявляється.

R7.2 завершено в зазначеному обсязі. Далі — решта форм і навігації R7, насамперед профіль та групи, з такими самими перевірками фокусу й відновлення. Вимірювання SQL/API/DOM і приймання R6 на живому PostgreSQL/Discord залишаються окремими пунктами. На VPS не розгорнуто; весь R6/R7/R8 не позначено завершеним.

Відкат — попередній повний пакет 3.8.93. SQL-міграцій, зміни cron чи протоколу bot/contract немає.
