# R6.5 — зрозумілий стан автоматизацій

Dashboard **3.8.78**, bot **3.6.6**. 14.10.2026, Europe/Kyiv.

## Результат

На головній сторінці керування та у розділі Discord з’явився спільний огляд очищення учасників, попереджень про ніки й неактуальних профілів. Кожна картка показує стан, причину, останній результат, орієнтир наступного запуску та доречний перехід. Це знімок зі сховища на час відкриття сторінки; час знімка й дат зазначено за Києвом. Нового фонового опитування немає.

Напис «увімкнено» раніше описував параметр, але не підтверджував роботу виконавця. Новий огляд відрізняє налаштування від чинного блокування операції й збереженої історії. Час наступного запуску позначений як очікуваний: сайт не бачить локальний файл наступного виклику cron і не може гарантувати фактичний момент виконання.

| Ситуація | Що показано |
|---|---|
| Чинне блокування з власником, датою початку та майбутнім строком дії | Виконується; підсумок ще очікується |
| Блокування збереження налаштувань очищення | Збереження |
| Пауза з уже відправленим запитом і чинним виконавцем | Зупинка; потрібен результат запиту |
| Прострочене блокування | Не підтверджує виконання |
| Незавершена спроба без чинного виконавця або непевні виключення | Потрібна звірка |
| Збережена помилка чи попередження | Потрібна увага; остання помилка не приховується |
| Увімкнено без першої перевірки | Очікує першого виклику або перевірки |
| Немає автоматичного виклику очищення понад 3 хвилини | Перевірити планувальник |
| Автоматизацію вимкнено | На паузі; ручні дії доступні окремо |
| Не прочитано сховище | Дані недоступні; не підставляється успіх або вимкнений стан |
| Правило очищення має некоректні булеві параметри чи строк | Перевірити правило або вибрати строк |
| Перевірка профілів знайшла кандидатів, автовидалення вимкнено | Є кандидати; перехід до перегляду |

Для очищення після збереженого автоматичного виклику використано орієнтир 10 секунд при незавершеному скануванні, інакше 60 секунд. Це не обіцяє наступного виключення: готовність кандидата, помилки, пауза та cron backoff змінюють фактичний час. Для ніків обирається раніша дата пріоритетної черги або повного сканування; зміна шаблону робить сканування актуальним зараз. Для профілів обирається раніша дата увімкненої перевірки чи очищення. Прострочені дати не пересуваються вперед, щоб не приховувати затримку.

## Переходи та дизайн

Посилання непевного результату відкриває `/dashboard/discord/cleanup?tab=uncertain#cleanup-members-title` одразу у вкладці «Потребують уваги». Сервер і клієнт використовують однакову початкову вкладку; наступне оновлення списку її зберігає. Невідомі й повторені параметри tab повертають стандартну вкладку учасників.

Переходи до `#nickname-automation` та `#account-automation` відкривають потрібну приховану секцію ManagementSections і прокручують до конкретної картки. Панелі залишаються змонтованими, тому незбережені поля не губляться. Чинні посилання на секції й клавіатурна навігація збережені.

Нові стилі ізольовані у CSS module й використовують системні amber-токени, поверхні, текст і межі. На широкому екрані — три картки; на вузькому — одна колонка. Перевірено довгі помилки й дев’ять ширин від 320 до 1920 px. Спільні таблиці стилів, фон, сторінка журналу та прийняття правил не змінені.

## Читання й права

Діагностичний loader читає до дев’яти документів через getAll. У PostgreSQL це **один додатковий параметризований SELECT**; інші читання чинних сторінок залишаються окремими. Якщо Discord guild ID не заданий, читаються п’ять документів для інших автоматизацій, а очищення учасників позначається недоступним. Відсутній документ після успішного читання використовує чинні початкові значення; помилка читання не використовує кешований або початковий стан як доказ доступності.

Для політики ніків, їхньої історії та профілів використано ті самі нормалізатори, що й у виконавців. Нові експортовані імена лише відкривають чинні функції для діагностики. Виконавці, cron, Discord REST, правила кандидатів, захист додаткових ролей, пауза R4 та транзакції R1/R6.4 не змінювалися.

Читання має дедлайн відповіді 2 секунди. Дедлайн не скасовує запит БД, який уже почався; результат такого пізнього читання не публікується. Повторів читання й викликів Discord REST у loader немає. Картки не викликають виконавців, не вмикають автоматизації, не відправляють сповіщень та не видаляють дані. У браузер передаються лише готові картки; власник lease, токен керування, actor ID й службові документи не передаються.

На головній сторінці огляд читається й відображається лише користувачам із правом керування Discord. Сторінки Discord та очищення перевіряють сесію й право до читання даних. Окремого API для нового огляду немає.

## Перевірки

Машиночитаний звіт: [R6_5_VALIDATION_2026-10-14.json](R6_5_VALIDATION_2026-10-14.json).

- `npm run check:automation-status`: 34 перевірки чинних модулів, включно зі збоями й дедлайном. Додано до verify та build:ci перед збіркою.
- `TEST_DATABASE_URL=... npm run test:automation-status`: 8 інтеграційних сценаріїв у приватній схемі PostgreSQL 16.15 UTF8, що видаляється після перевірки. Підтверджено один SELECT, відсутність змін документів і помилку реального сховища.
- Chromium: 11 сценаріїв на фактичних компонентах і стилях, 9 ширин, 0 помилок сторінки, 0 запитів на мутацію від нових карток.
- Next standalone: 13 перевірок неавторизованого доступу, перенаправлень, no-store та Origin; без production-сесій або Discord токенів.
- Повний build:ci, TypeScript, ESLint та production build; перевірка відповідності вихідного коду файлам фактичного Docker builder COPY.

VPS, production БД, Discord та Battle.net у сеансі не змінювалися. Повний авторизований наскрізний сценарій на живому Next/Discord не тестувався. Browser QA використовує фактичні компоненти з локальними HTTP fixtures; SQL QA — окрему БД. Docker engine не запускався; збірка перевірена з усіма входами builder.

## Оновлення й наступні роботи

Нової SQL-міграції, змін cron або bot немає. Оновити dashboard штатною процедурою. Обмеження відкату після перенесень ID груп з [R6.4](R6_4_GROUP_ASSIGNMENTS_2026-10-12.md) залишаються чинними.

R6.5 завершує огляд цих трьох автоматизацій та конкретні переходи до їхніх дій. Інші автоматизації, розширення контекстних дій заявок/публікацій та навігація інших списків залишаються для наступних підетапів R6. Зміна конфліктного збереження параметрів інших автоматизацій, ручне підтвердження непевного результату й новий heartbeat cron у цей реліз не входять. R7 — узгодження решти дизайну та виміряна оптимізація; R8 — новий функціонал після завершення наявного.
