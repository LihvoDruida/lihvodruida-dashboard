# R7.3 — профіль, групи та швидкодія важких перевірок

Dashboard **3.8.96**, bot **3.6.9**, contract **1.1.1**. База — повний пакет 3.8.95. Перевірено 15.10.2026.

## Продовження робочих сценаріїв

Браузер із production React-компонентами попереднього пакета відтворив BODY-фокус після збереження імені, персонажів та групи: кнопка ставала disabled або замінювалася. Ці форми тепер використовують спільний useActionFocus, постійні status-регіони, aria-atomic і фокусований результат. Результат не додає зайвої зупинки до звичайної Tab-послідовності. Якщо користувач перейшов до іншого елемента, завершення операції не перехоплює фокус.

Окремо виправлено повторне використання кнопки React-ом: після видалення групи той самий DOM-елемент міг стати кнопкою видалення наступної групи. Для цього сценарію задано явний перехід до результату. Так само форма персонажів може замінити Save на перевірку непевного результату в тому самому DOM-вузлі. Початкова поведінка useActionFocus для решти форм збережена.

Під час GET-відновлення імені з matching operationId повідомлення «Збереження підтверджено» більше не очищається відразу після accept(). Чернетки, revision-контроль та явні дії з правами залишаються в наявних сценаріях. Додаткового автоматичного POST немає.

## Виміряна швидкодія

Однаковий Chromium, production bundle, контрольований API та синтетичні дані. Це вимірювання локального браузера, не VPS або живої бази.

| Сценарій | 3.8.95 | 3.8.96 |
|---|---|---|
| 20 введених символів у назву, каталог із 2 000 груп | 40 000 нормалізацій усього каталогу | 0 повторних нормалізацій каталогу |
| Зміна чотирьох рейдових ролей, 5 000 кандидатів | 4 повторні сортування | 0 повторних сортувань |
| TypeScript, другий послідовний запуск | 18,327 с | 2,621 с із теплим кешем |
| TypeScript, перший запуск | 19,524 с | 18,132 с без кешу |

Пошуковий індекс груп тепер залежить від серверного каталогу; редагування чернетки його не перебудовує. Пошукова фраза нормалізується один раз, відбір запам’ятовується до зміни фрази або каталогу. Новий каталог після запису/читання перебудовує індекс, тому пошук враховує свіжі дані.

У формі персонажів сортування залежить лише від списку кандидатів. Вибрані та доступні ключі перевіряються через Set, а похідний список мейнів запам’ятовується. Початковий DOM з 5 000 кандидатів містить лише 8 рядків; явне розгортання і ліміт 200 вибраних персонажів збережені.

Час введення з браузерного harness наведено у JSON як допоміжне спостереження; він включає синтетичні клавіатурні події. Критерій оптимізації — усунення зайвої роботи та незмінна поведінка, не гарантований час відповіді на будь-якому пристрої.

## Важкі перевірки

TypeScript incremental state перенесено до `.next/cache/typecheck/tsconfig.tsbuildinfo`. Наявний locked BuildKit mount `.next/cache` зберігає його між збірками. Повний список source-файлів, strict, noEmit, тайм-аут і контроль коду завершення збережені; успішна перевірка не замінена перевіркою наявності кеш-файлу.

Окремий важкий suite компілює повний проєкт із тимчасовим probe-файлом: створює кеш, повторює незмінений запуск, змінює той самий файл на реальну помилку TS2322 та відновлює його. **4/4**: cached success стає exit 2 після помилки, а виправлений файл знову дає exit 0. Тимчасовий конфіг і probe видаляються у finally. Це окрема QA-команда: багаторазова повна компіляція не додається до кожної Docker-збірки.

`inspect-ci` також розпізнає наявний post-build standalone gate замість хибного попередження про відсутність production build.

Команди з dashboard:

```sh
npm run check:profile-groups-browser
npm run check:typecheck-cache
npm run check:workflow-accessibility-browser
npm run build:ci
npm run lint
```

Браузерні команди потребують Playwright, esbuild і Chromium через MISTBLOSSOM_QA_MODULES / MISTBLOSSOM_QA_CHROMIUM. MISTBLOSSOM_QA_OUTPUT задає каталог звіту. Browser QA не стає залежністю production image. Важкий compiler-suite може записати JSON у MISTBLOSSOM_QA_REPORT.

## Перевірки та межі

Новий browser suite має **12 сценаріїв**: три успішні збереження, два великі каталоги, непідтверджений запис імені й персонажів, GET-відновлення receipt, відсутність перехоплення фокусу, видалення групи, status/adaptive на дев’яти ширинах 320–1920 px та відсутність runtime-помилок. Окрема регресія R7.2 перевіряє заявки, публікації, діалог рейду й reduced motion. Остаточні результати: [R7_3_VALIDATION_2026-10-15.json](R7_3_VALIDATION_2026-10-15.json).

Навантажувальний обсяг тут — локальні каталоги UI та повна TypeScript-компіляція. Запити до живих PostgreSQL/Discord, Docker build, NVDA/TalkBack та справжній RSC refresh на VPS не перевірялися. SQL/API-продуктивність на VPS не оголошується поліпшеною. Збільшення частоти polling, нових SQL-схем, змін бота чи дизайну журналу немає.

R7.3 завершено в описаному обсязі після проходження зафіксованих перевірок. Далі — інша навігація/форми R7 та вимірювання SQL/API на стенді. Живе приймання R6 залишається за майбутньою перевіркою користувача. Відкат — повний пакет 3.8.95; для холодної TypeScript-перевірки достатньо прибрати тільки каталог `.next/cache/typecheck`.
