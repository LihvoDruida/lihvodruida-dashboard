# R7.5 — форма та списки очищення Discord

Dashboard **3.8.98**, bot **3.6.9**, contract **1.1.1**. 15.10.2026.

Форма зберігає поточний вибір після непідтвердженого запису, а повідомлення читання списку відокремлено від результату дії. Фокус після паузи та останнього «Показати ще» переходить до постійного результату. Розгорнутий список має явний режим знімка з окремим оновленням через GET.

## Відтворення на 3.8.97 та результат

Оригінальний компонент із попереднього повного архіву перевірено тим самим Chromium-стендом. Сім baseline-проб фіксували дефекти; це не сім успішних перевірок виправленої поведінки. Фінальна версія пройшла 15 сценаріїв.

| Сценарій | 3.8.97 | 3.8.98 |
|---|---|---|
| Пауза прибирає власну кнопку | Фокус на BODY | Фокус на status результату |
| Помилка читання історії | «Виключень ще немає» | Явна помилка та GET-повтор |
| Читання відновилося | Стара помилка лишалася | Помилка списку очищена |
| 100 рядків: один фоновий цикл | 4 GET сторінок | 1 GET стану, 0 читань сторінок |
| Конструктори Intl.DateTimeFormat, mount + той самий цикл | 800 | 1 спільний форматер |
| Форма зі змінами: один фоновий цикл | 1 читання | 0 читань, чернетка збережена |
| Непідтверджене збереження увімкнення | Вибраний прапорець скидався | Вибір зберігається |
| Останнє «Показати ще» прибирає кнопку | Фокус на BODY | Фокус на status списку |

Лічильники вимірюють роботу в контрольованому сценарії, а не час відповіді production PostgreSQL, FPS або пропускну здатність VPS. Формат дат і часовий пояс Europe/Kyiv збережені.

## Зміни

- Чернетка ролі, календарного строку та увімкнення позначає форму dirty й призупиняє власне фонове читання. Спільний RSC refresh також бачить dirty/busy. Явне GET-читання оновлює збережений стан, зберігаючи незбережені поля.
- POST вимагає `ok === true` і коректного мінімального підтвердження settings або scan. HTML, truthy-рядок і неповний payload не видаються за успішний запис. Відновлення лише перечитує стан; POST не відтворюється автоматично.
- Пауза залишається доступною під час збереження. Пізня відповідь попереднього запиту ігнорується. Підтверджена пауза узгоджує прапорець зі збереженим станом, не скидаючи інші поля.
- Мутації та читання мають окремі status-регіони й керування фокусом. Завершення дії не забирає фокус, якщо користувач уже перейшов до іншого елемента. Вкладки мають клавіатурну навігацію й зберігають фокус.
- Для списків понад 25 рядків фоновий GET із `summary=1` повертає збережені налаштування, лічильники й стан виконання. Маршрут зберігає авторизацію, перевірку прав, tab і no-store. Він не викликає читання рядків чи Discord REST.
- Рядки розгорнутого списку позначено знімком. «Оновити показаний список» перечитує сторінки через GET, не запускаючи сканування. При новій перевірці читання починається з її першої сторінки; різні scanId не змішуються. Списки до 25 рядків далі оновлюються автоматично.
- Повторний курсор і проміжна сторінка без нових рядків зупиняють розгортання з помилкою; попередній знімок зберігається. Об’єднання через Set перевірено на 10 000 попередніх і 100 нових рядках.

Частота панелі збережена: 10 секунд при увімкненій автоматизації, 30 на паузі; читання лише у видимій вкладці й без іншої дії або чернетки. Явне оновлення розгорнутого списку досі читає кілька сторінок під одним загальним дедлайном 15 секунд; воно не стало одним запитом. Ліміт окремого GET — 12 секунд. Дедлайни POST: settings 20 секунд, pause 10, scan 40, із загальними межами дії 25/45 секунд.

## Перевірки

- `npm run check:cleanup-view` — **17/17**: пагінація, зміна scanId, некоректний payload, відсутність прогресу, лінійне об’єднання, авторизація справжнього GET-маршруту й відсутність читання рядків у summary.
- `npm run check:cleanup-panel-browser` — **15/15**: production React і чинні CSS у Chromium 153.0.8010.0; фокус, помилки, чернетка, непідтверджені відповіді, пауза під час запиту, пізня відповідь, явний GET refresh, клавіатура й дев’ять ширин 320–1920 px. Runtime-помилок немає.
- Наявна регресія `check:discord-member-cleanup` — **101** перевірка політики, сховища, пагінації, lease та cron у CI.
- Усі перевірки `build:ci` до `inspect:ci` пройшли; inspect перевірив 514 файлів без блокерів. Процес повернув exit 0, але перенаправлений журнал обривається під час генерації сторінок. Тому остаточні TypeScript, production build і standalone перевірені окремо з повним результатом.
- Остаточні `npm run typecheck`, `npm run lint`, `npm run build` — exit 0. Next 16.3.5; завершальна збірка 9 секунд на локальному теплому кеші, без порівняльної заяви про швидкість production.
- `npm run check:standalone` — **6/6**: реальний packaged Sharp render, фон/шрифти, відсутність source/CI у пакеті, старт готового Next server і no-store liveness. 4 057 файлів, 84 362 242 байти.

Новий швидкий `check:cleanup-view` включено у `verify` та `build:ci`. Browser-suite лишається окремою перевіркою й потребує зовнішніх Playwright, esbuild та Chromium; нових production-залежностей немає. Шляхи до модулів/Chromium можна задати через `MISTBLOSSOM_QA_MODULES` та `MISTBLOSSOM_QA_CHROMIUM`, каталог JSON-звіту — `MISTBLOSSOM_QA_OUTPUT`. Baseline використовує `MISTBLOSSOM_TEST_CLEANUP_SOURCE` із попереднім компонентом.

## Межі та наступний крок

Це локальне завершення зазначеного обсягу R7.5. SQL-схема, правила відбору та виключення, cron, бот і контракт не змінювалися. Збереження чернетки діє в межах змонтованої форми; нового сховища для відновлення після reload немає. Розгорнуті рядки можуть належати попередньому знімку, доки користувач явно їх не перечитає; стан виконання оновлюється окремо.

Живі PostgreSQL/Discord, Docker/VPS, реальні NVDA/TalkBack та виробничі SQL/API-метрики в цьому запуску не перевірялися. Приймання R6 користувач проведе пізніше. Наступний обмежений пакет — **R7.6: Discord-ролі Статика та решта форм налаштувань**; весь R7 не позначено завершеним.
