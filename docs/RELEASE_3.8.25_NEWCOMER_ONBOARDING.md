# 3.8.25 — Discord newcomer onboarding

## Що змінилось

- Додано окремий idempotent onboarding для нових Discord-учасників.
- Перший запуск після деплою створює baseline чинного складу сервера й не розсилає welcome старим учасникам.
- Новий учасник отримує приватне повідомлення з:
  - привітанням;
  - кнопкою **«Прийняти правила»**;
  - кнопкою через чинний rules interaction; персональне підписане посилання формується вже після кліку й привʼязується до Discord ID користувача;
  - одноразовою первинною перевіркою серверного ніку;
  - допустимими структурами ніку та короткою інструкцією, як його змінити;
  - посиланнями на правила, оголошення, рейди й основний чат.
- Роль після прийняття правил береться з чинного guild-rules повідомлення; fallback — налаштована newcomer role.
- Після прийняття правил onboarding лише фіксує завершення, а подальшу перевірку ніку передає вже існуючому `processNewcomerNicknameRoleGrant`/nickname scheduler.
- Додано `/api/dashboard/discord/onboarding/automation`, який викликається self-hosted cron кожну хвилину.
- У `/guild` додано компактний блок швидкої Discord-навігації з чотирма ключовими каналами.

## Безпека

- Bot container як і раніше не отримує `DISCORD_BOT_TOKEN` і не підключається до Discord Gateway.
- Новий scheduler працює через dashboard REST API, де bot token уже ізольований.
- Internal endpoint закритий bearer-auth перевіркою й доступний через internal-host gate тільки для сервісних запитів.
