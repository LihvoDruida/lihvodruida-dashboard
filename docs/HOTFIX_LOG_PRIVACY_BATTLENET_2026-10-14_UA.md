# Dashboard 3.8.85 — виправлення за експортом логів

Дата: 14.10.2026. База: повний пакет R6.8 / 3.8.84; bot 3.6.7.
Функціональний етап залишається R6.8. R6.9, R7 та R8 цим hotfix не завершено.

## Підтверджені дефекти та зміни

1. **Секрети в логах.** Підписаний двокомпонентний receipt прийняття правил
   міг залишатися у `filename` та `pathname`: попереднє маскування JWT із трьох
   компонентів його не охоплювало. Спільна функція тепер очищує URL query і
   fragment, вкладені URL, типові секретні ключі й двокомпонентні receipts.
   Браузер прибирає query до обрізання рядка; сервер повторно очищує недовірений
   звіт. Захист застосовано до console, нових structured logs, Discord mirror,
   а також читання історичних записів для інтерфейсу та експорту.
   Історичні рядки БД не переписуються; раніше завантажені копії експортів
   заднім числом не змінюються. Оригінальний діагностичний файл збережено.
   Маскування до обрізання також захищає від часткового розкриття довгого
   токена. Регулярні вирази не повторюють повний пошук із кожної позиції
   довгого суцільного рядка; окрема перевірка обмежує CPU-час цього сценарію.
2. **Зайві повтори HTTP GET.** `ApiHttpError` після відповіді 400/401/403/404
   помилково трактувався як мережевий збій. Повтор заборонено на цьому шляху;
   явна політика повторів для тимчасових HTTP і мережевих збоїв збережена.
3. **Battle.net.** Обмін OAuth code та отримання application token мають
   дедлайн й нуль автоматичних повторів POST; userinfo також має дедлайн.
   Callback записує етап, регіон, дозволений шлях upstream, HTTP-код і тип
   помилки без тіла відповіді провайдера. Відсутній WoW-профіль, відмова доступу
   та тимчасова недоступність мають окремі повідомлення українською.
   При невдалому скануванні збережені персонажі не перезаписуються порожнім
   результатом; перевірка дублювання персонажів залишається обовʼязковою.
4. **Повторювана помилка nativeIframe.** У вихідному коді застосунку такого
   ідентифікатора немає. Вузька сигнатура duplicate declaration з URL самої
   сторінки, без посилань на JS bundle, позначається як *ймовірний сторонній
   скрипт*. Подія залишається в логах як warning; загальний toast збою застосунку
   для цієї сигнатури не показується. Невідомі джерела та помилки JS-файлів
   залишаються errors. Джерело стороннього скрипту не доведено й не видалено.
5. **Діагностика cron / HTTP 421.** Чинний вузький захист Host з 3.8.79
   збережено. Додано authenticated GET до того самого маршруту
   `/api/dashboard/discord/profile-nicknames/automation`, який повертає лише
   режим read-only та версію. Штатна перевірка запуску викликає його з cron
   контейнера з таймаутом 5 секунд. GET не читає/виконує чергу й не надсилає
   запити Discord. POST та перевірка токена залишаються захищеними.

## Як трактувати початковий експорт

Експорт містить 2064 записи, 282 відмови Host; остання відмова — 15:48 UTC.
Новий Gateway ready — 15:53 UTC; експорт завершено 15:56 UTC. Цього вікна
недостатньо для висновку про черговий 15-хвилинний запуск cron після оновлення.
HTTP 421 у старих рядках не є доказом збою нового runtime.

Сім помилок Battle.net «Not Found» пізніше змінилися успішним підключенням.
Попередніх метаданих недостатньо, щоб довести конкретний upstream endpoint
або стан облікового запису. Нові структурні поля дадуть ці відомості при
повторенні; віддалену проблему Blizzard цим пакетом не оголошено усунутою.

## Перевірка та встановлення

Нові команди `check:log-privacy` та `check:battlenet-resilience` включено у
`verify` і `build:ci`; `check:internal-cron-proxy` розширено read-only GET.
Результати поточного запуску: `HOTFIX_LOG_PRIVACY_VALIDATION_2026-10-14.json`.

Оновити dashboard зі штатним перезбиранням образу та виконати штатну перевірку
`deploy/scripts/internal-auth-check.sh` у запущеному Compose. Вона має показати
версію 3.8.85 для profile-nicknames. Нової SQL-міграції, cron-задачі або версії
бота немає. Наявні Discord transport/performance та R1–R6.8 зміни збережено.

Пакет перевіряється локально. Розгортання на VPS, жива OAuth-авторизація
Blizzard та реальні Discord-операції під час цієї роботи не виконувалися.
