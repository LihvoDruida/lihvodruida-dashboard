# Відеофон авторизації — 15.10.2026

Dashboard **3.8.101**, bot **3.6.9**, contract **1.1.1**.

До оформлення 3.8.100 додано систему відеофону з наданого MHTML. Ті самі три MP4, беззвучне відтворення в межах сторінки та плавне перемикання працюють під карткою входу. Додаткової навігації, iframe або player-скриптів немає.

## Відповідність шаблону

| Елемент | Реалізація |
|---|---|
| Ролики | Hyjal02.mp4 → Zephras_01.mp4 → WowF_TheBarrens_01.mp4 → початок |
| Джерела | Три оригінальні HTTPS URL Blizzard CDN із MHTML |
| Підкладка | Наявний локальний пейзаж, cover, масштаб 1,06 |
| Відео | muted, playsInline, preload auto, cover, масштаб 1,12 |
| Початкова поява | opacity за 1,6 секунди після фактичного playing |
| Зміна ролика | opacity за 1 секунду; старт наприкінці попереднього ролика |
| Затемнення | Радіальні й лінійний градієнти з CSS шаблону |

MHTML містить збережений DOM із трьома video та CSS, але не початковий JavaScript перемикання. Контролер написано окремо для відтворення цієї видимої системи; тотожність невідомого JS-коду чи початкової випадкової сцени не заявляється. Порядок відповідає DOM архіву.

## Відтворення й відновлення

Джерела встановлюються після гідратації, коли вкладка видима й немає reduced motion або data saver. До цього видно локальний постер. Наступний ролик стає видимим лише після playing, тож очікування мережі не підміняє поточну картинку порожнім відео. Після переходу попередній ролик зупиняється.

Помилкове джерело пропускається та від’єднується, щоб зупинити його завантаження. Якщо доступний лише один ролик, він продовжує відтворюватися по колу. Якщо всі джерела недоступні, autoplay відхилено або запуск не підтвердився за 15 секунд на джерело, залишається постер. Автоматичного нескінченного повтору немає, форма входу не переходить у busy.

У прихованій вкладці всі ролики призупиняються; після повернення відтворення поновлюється. Reduced motion/data saver прибирають джерела та повертають постер; після зняття цих обмежень відео запускається знову. Демонтаж прибирає listeners/таймери, зупиняє media й видаляє src. Відео декоративне, без controls і tab stop; форма залишається поверх нього та доступною клавіатурою.

Ролики стримляться з CDN, як у шаблоні, і не включені у ZIP. Перевірені розміри: 10 446 580, 6 626 306 та 8 084 533 байти; усі H.264 1920×1080, приблизно 13–16 секунд. preload auto дозволяє браузеру завантажувати їх наперед. Без мережі доступний локальний постер, але не самі ролики.

Під час візуального контролю виявлено, що чинний ICO не декодувався як емблема в тестовому Chromium, хоча наявний PNG декодувався. Резервний бренд тепер використовує існуючий `/android-chrome-192x192.png`. Емблема з налаштованого Discord-сервера не змінювалася.

## Перевірки

- Три оригінальні URL відповіли HTTP 200. Ролики завантажено для QA, перевірено ffprobe й SHA-256; копії не включено до релізу.
- `check:login` — **26/26**; чинна auth-lifecycle регресія також пройшла у CI.
- Production browser — **29/29**: збережені сценарії входу/адаптивності, реальний H.264 decode трьох оригінальних роликів, ротація і повернення до початку, один здоровий ролик, mobile inline/cover, прихована вкладка, reduced motion, data saver, очікування наступного playing, відмови, blocked autoplay і deadline. Дев’ять ширин 320–1920 px; runtime-помилок немає. Desktop/mobile візуально оглянуто, емблема декодується.
- Для відтворюваності оригінальні байти MP4 у тесті підставляються на ті самі URL із підтримкою Range; працює справжній браузерний decoder, а не макет video. Негативні мережеві сценарії контрольовані. Browser-suite приймає `MISTBLOSSOM_QA_VIDEO_DIR` з трьома оригінальними файлами; без нього запускаються базові 17 сценаріїв. Інші змінні стенда залишились `MISTBLOSSOM_QA_MODULES`, `MISTBLOSSOM_QA_CHROMIUM`, `MISTBLOSSOM_QA_OUTPUT`.
- Повний `build:ci` та ESLint — exit 0. Після фінального звільнення невдалих джерел і PNG fallback додатково пройшли ESLint змінених файлів, TypeScript, production build, browser 29/29 та standalone **6/6**.

Машинний звіт: [LOGIN_VIDEO_VALIDATION_2026-10-15.json](LOGIN_VIDEO_VALIDATION_2026-10-15.json).

Фізичні iOS/Android та безперервне браузерне відтворення безпосередньо з живого CDN не перевірялись. Перевірено mobile viewport і точні медіабайти; доступність CDN перевірено окремими HTTP-запитами. Реальний OAuth і аварійний POST не виконувалися. Auth API, права, SQL, cron і бот не змінювалися; на VPS пакет не розгорнуто. Це доповнення авторизації, не закриття решти дорожньої карти.
