# 3.8.68 — очищення та мережеві помилки Docker-збірки

Збірка з наданого логу зупинилася на `auth.docker.io` через DNS хоста `127.0.0.53`. Код застосунку ще не збирався. Заміна Dockerfile прибирає один зайвий запит до Docker Hub, але робочий DNS потрібний для образів і залежностей.

## Зміни

- В обох Dockerfile використано вбудований frontend BuildKit замість зовнішнього `docker/dockerfile:1.7`. Кеші npm/Next, security overlays та runtime-права збережено.
- Збірку винесено в `build-images.sh`: dashboard і bot запускаються послідовно. Команди `make up`, `restart`, `deploy`, `rebuild-dashboard`, `rebuild-bot` використовують один шлях збірки.
- Якщо збірка падає, наступна не починається, зберігається вихідний код помилки, запускається читальна діагностика DNS/HTTPS. Робочі контейнери не зупиняються helper-скриптом.
- `make restart` викликає `compose down` тільки після успішної збірки.
- `make network-check` перевіряє хостовий DNS/HTTPS Docker Hub, npm і Debian. Автоматично не змінює resolver, не перезапускає Docker й не видаляє кеш. Інструкція: `docs/BUILD_NETWORK.md`.
- Вилучено 63 файли (9 959 613 байтів): старі фони й іконки без runtime-посилань, згенеровані знімки та докладні тимчасові логи/результати попередніх перевірок. Підсумки 3.8.66 і 3.8.67 збережено.
- `.dockerignore` додатково виключає QA, документацію dashboard, ZIP/tsbuildinfo й старі каталоги UI-ресурсів, які можуть лишитися при накладанні архіву на стару папку.
- Збережено використовувані welcome-ресурси, шрифти, favicon/PWA, основні та історичні URL рейдових мініатюр, runtime-код, перевірки, міграції й експлуатаційну документацію.

## Межі

Збірка Next використовувала наявні залежності, включно з Next.js 16.3.5; package/lock зберігають базовий Next.js 16.3.3, а Docker — наявні pinned security overlays. Чистий npm ci не виконувався. Сервер автоматично не змінювався.
