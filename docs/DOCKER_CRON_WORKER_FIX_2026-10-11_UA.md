# Виправлення Docker-збірки: cron worker

У журналі VPS збірка панелі зупинилася на `check-discord-member-cleanup`:

```text
sh: 0: cannot open /repo/deploy/cron/run-job.sh: No such file
```

Причина: worker був у репозиторії та змонтований у cron-контейнері, але
`dashboard/Dockerfile` не копіював його в окремий етап `builder`, де
`build:ci` запускає поведінкові перевірки. Збірка з повного локального
репозиторію приховувала цю відсутність.

Після наявного `COPY deploy/cron/run-cron.sh ...` додано:

```dockerfile
COPY deploy/cron/run-job.sh /repo/deploy/cron/run-job.sh
```

`check-platform-hardening.cjs` тепер перевіряє копіювання обох cron-скриптів
саме в `builder`, навіть під час перевірки з повного локального репозиторію.
Перевірки автоматизації залишилися ввімкненими.

Для повторного розгортання після оновлення файлів проєкту:

```sh
make up
```

Очищення Docker-кешу не потрібне: змінений `COPY` автоматично оновить
відповідний шар і повторить `build:ci`.

Перевірка виконувалася в окремому каталозі, сформованому за інструкціями
`COPY` етапу `builder` з урахуванням `.dockerignore`. Залежності взяті з
наявного локального встановлення з тими самими security-overlay версіями
Next.js, React і Sharp. До виправлення цей каталог відтворив відсутність
worker; після виправлення він включає обидва cron-скрипти. Окремо перевірено,
що новий аудит відхиляє Dockerfile без worker навіть за наявності локального
файлу. Результати наведено в `DOCKER_CRON_WORKER_VALIDATION_2026-10-11.json`.

Це перевірка файлів і команд збірки, а не запуск Docker-образу. Docker у
середовищі перевірки недоступний; сам образ і розгортання на VPS тут не
виконувалися. Виключення реальних учасників Discord не запускалося.
