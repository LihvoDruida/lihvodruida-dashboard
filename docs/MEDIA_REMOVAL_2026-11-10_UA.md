# Dashboard 3.18.0 — очищення стрімерів зі збереженням відеофону

Змінено наданий архів Dashboard/Bot. Робочий VPS, PostgreSQL, Discord і окремий публічний Site не змінювалися.

## Що змінено

- Весь `dashboard/src/lib/streamers/`: Twitch/YouTube/TikTok, токени, шифрування, опитування, EventSub, Discord-сповіщення, діагностика й retention.
- Сторінку `/dashboard/streamers`, компоненти, CSS та пункт адміністративної навігації.
- API `/api/dashboard/streamers`, `/api/dashboard/streamers/automation`, `/api/site/streamers`, `/api/integrations/twitch/eventsub`.
- Cron worker 30 секунд, запис у каталозі автоматизацій, винятки proxy та capability `streamers:read:v1`.
- Вісім `STREAMER_*` змінних із шаблону конфігурації; специфічні Twitch/YouTube/TikTok гілки спільного cooldown.
- Відеофон повернуто: усі шість MP4, програвання трьох сцен, переходи, CSS і кешування збережено. Він працює на вході та сторінці прийняття правил; reduced motion, data saver та помилки залишають постер.
- Окремі тести/інструкції видаленого модуля; спільні перевірки HTTP, API-захисту й авторизації збережено та адаптовано.

Додатково видалено `access.ts`, `status.ts`, старий `discordInteractionDedupe.ts`, три невикористані UI-компоненти (`ImpersonationToast`, `MobileNavSafeAreaSync`, `PagePrimitives`), три архівні довідники та три дублікати PNG. Тести replay-захисту переведено на чинний `discordInteractionOutbox.ts`; його колекція даних збережена. Старі URL `raid-normal.png`, `raid-heroic.png`, `raid-mythic.png` мають постійні перенаправлення на `normal.png`, `heroic.png`, `mythic.png`.

Нових сторонніх залежностей немає. Окремих npm-пакетів тільки для стрімерів у початковому проєкті не було.

## Оновлення сервера

1. Зробити `make backup` зі старим кодом; зберегти робочі env. Зупинити старий cron: `docker compose stop cron`.
2. Замінити код. Під час копіювання поверх старого дерева фізично видалити старі каталоги/файли зі списку `REMOVED_MEDIA_FILES.txt` у корені (він актуалізований для 3.18.0 та не містить відновленого відеофону). Просте розпакування ZIP поверх старого каталогу не видаляє старі файли. Надійний варіант — новий каталог коду та перенесення лише робочих env за основною інструкцією.
3. Виконати `make up` з новим кодом. Пересоздати cron: `docker compose up -d --no-deps --force-recreate cron`. Новий cron не має задачі стрімерів. До очищення даних переконатися, що старі репліки Dashboard і cron більше не працюють.
4. Переглянути кількість старих записів без збереження змін:

```bash
docker compose exec -T dashboard node dashboard/scripts/remove-media-data.mjs
```

5. Застосувати остаточне очищення:

```bash
docker compose exec -T dashboard node dashboard/scripts/remove-media-data.mjs --apply
```

Без Docker: у каталозі `dashboard`, із заданим `DATABASE_URL`, виконати `npm run db:remove-media`, потім `npm run db:remove-media -- --apply`.

Очищення — одна транзакція: канали/токени, події, ідентичності, квоти, EventSub-сигнали, налаштування, стан автоматизації, квитанції й ідентифіковані блокування публікацій, cooldown лише видалених платформ, журнали цього модуля. Повторний запуск не змінює результат. За помилки транзакція відкочується. Спільні таблиці не видаляються; записи рейдів, заявок, профілів, Discord-публікацій інших модулів та паузи Battle.net/Raider.IO зберігаються.

6. Із робочих env прибрати всі вісім `STREAMER_*` ключів, перелічених у `REMOVED_MEDIA_FILES.txt` / попередньому шаблоні. У кабінетах провайдерів відкликати більше не потрібні токени й EventSub-підписки; прибрати окремий виняток WAF для старого callback, якщо його створювали.
7. В окремому публічному Site видалити блоки стрімерів і виклики старого bridge API. Його джерел у цьому архіві немає, тому зміни Site тут не виконані.

Видалення рядків PostgreSQL не знищує старі резервні копії, WAL або сторонні копії даних. Уже опубліковані повідомлення Discord та матеріали на Twitch/YouTube/TikTok також не видаляються цим оновленням.
Після очищення дані модуля можна повернути лише з бекапу; старий моніторинг без квитанцій може повторити повідомлення.

## Перевірка

`npm run check:media-removal` перевіряє відсутність старого модуля, наявність шести фонових відео, SQL preview/rollback, точність видалення, збереження сторонніх записів та повторний запуск на PGlite.
Повний результат поточного прогону: `VALIDATION_MEDIA_REMOVAL_2026-11-10.md` у цій папці.
