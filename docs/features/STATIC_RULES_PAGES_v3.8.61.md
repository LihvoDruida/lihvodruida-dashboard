# Статик — окремі сторінки, журнал і вибір Discord-ролей (3.8.61)

## Маршрути

- `/discord/static` — огляд, активні запрошення на 24 години, керування складом та посилання на дочірні сторінки.
- `/discord/static/rules` — окремий Markdown-редактор для РЛ/адміна; перегляд для учасників. Публічне прийняття `/static/accept?t=...` працює як раніше.
- `/discord/static/events` — журнал подій з фільтром типу та пошуком, останні 250 записів з бази; лише читання.
- `/dashboard/settings` — налаштування Discord-ролей Статика у панелі адміністратора.

## API

- `GET /api/static/manage` більше не витягає повний журнал (лише склад, запрошення та метадані).
- `POST /api/static/manage` керує лише запрошеннями й складом: `save-rules` і `save-roles` прибрані з маршруту.
- `GET/POST /api/static/rules` — читання та редагування Markdown; запис тільки за роллю РЛ або адміністратора.
- `GET /api/static/events` — читання журналу для учасників Discord-сервера, без можливості модифікації.
- `GET/POST /api/dashboard/static-roles` — список реальних Discord-ролей та налаштування. Зміни доступні тільки адміністратору або власнику; сервер перевіряє ідентифікатори ролей, права бота і наявність активних підписантів.

## Примітки

- Роль Статика має бути нижчою за найвищу роль бота; керівна роль РЛ має існувати на сервері, але не мусить бути керованою ботом.
- Зміна ролі учасника заблокована, якщо вже існує активний склад: потрібно контрольоване перенесення.
- Адмін-сторінка не дає зберігати налаштування, коли Discord API не відповідає.
- Жодна стара база або колекція не мігрує: використовуються існуючі `staticRules*`.
- Під час збірки потрібно виконати `npm run typecheck`, `npm run check:static-sections-independent` і `npm run build`, а після деплою перевірити роботу під РЛ/адміном/офіцером на реальному Discord-сервері.
