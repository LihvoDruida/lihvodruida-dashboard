## v3.8.66 — згода перед роллю

- `GUILD_MEMBER_ADD` та `GUILD_MEMBER_UPDATE` запускають перевірку ролі Статика. Видача без дійсного `acceptedAt` знімається; відсутній запис також означає відсутність згоди.
- Видаляється виключно `memberRoleId` Статика окремим Discord DELETE, без заміни списку ролей.
- Підтвердження коду в DM транзакційно зберігає згоду до видачі ролі. Помилка Discord зберігає факт згоди й дозволяє повторити код.
- Повторна подія під час перевірки не губиться: обмежена черга повторює звірку; помилки мають три спроби з паузами.
- Звірка після READY/RESUMED та щогодини читає фактичних власників ролі, включно з людьми без запису про вступ.
- Перед зняттям повторно читаються згода й налаштування. Недоступність БД не трактується як відсутність згоди.
- Попередні прийняття правил лишаються дійсними після редакцій документа; бан і блокування продовжують забороняти роль.
- Читання журналу аудиту Discord не потрібне: законна видача ботом підтверджується збереженою згодою. Gateway-подія містить ролі учасника, але не виконавця зміни.

Потрібні `DISCORD_GATEWAY_ENABLED=1`, `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`, спільний `INTERNAL_API_TOKEN`, увімкнений **Server Members Intent** у Discord Developer Portal. Бот повинен мати **Manage Roles**, а його найвища роль має бути вище ролі Статика. Перевірка на реальному сервері тут не виконувалася.
