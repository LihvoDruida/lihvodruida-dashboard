# Discord-запис у рейд — повернення до попереднього меню

Дата: 15.10.2026. Dashboard **3.8.89**. Базовий архів: повний 3.8.88 із виправленнями аудитів CI. Бот 3.6.9 і shared contract 1.1.1 сумісні з відновленим сценарієм.

## Як працює запис

1. «Записатися в рейд» відкриває приватне меню з двома способами: «Мої персонажі» та «Вручну».
2. Для свого персонажа доступний персональний список із профілю. Для ручного запису спочатку обирається клас, потім спеціалізація цього класу. Кнопок «спеки 1/2» і «2/2» немає.
3. Меню показує лише поточний крок, вибраного персонажа або клас/спеціалізацію, початкову роль і збережений стан нагадування. Додано заголовок і значки класів.
4. «Далі · підтвердження» стає доступною після вибору. Вона одразу відкриває форму участі, ролі й нагадування. Форма відкривається локально ботом, без додаткового запиту до dashboard.
5. Запис і налаштування нагадування зберігаються лише після підтвердження. Відмова від нагадувань залишається прив’язаною до Discord ID і підтягується в майбутній акаунт сайту.
6. «Пропустити рейд» також потребує підтвердження у формі.

Для ручного запису роль початково визначається спеціалізацією, але в підсумковій формі її можна змінити, як у попередньому варіанті. Зміна класу очищає попередню спеціалізацію й блокує підтвердження до нового вибору.

Відновлено лише сценарій Discord. Модальне вікно запису на сайті та виправлення CSS/UI із 3.8.88 залишаються.

## Причина помилки відкриття повної модалки

Новий endpoint /api/internal/discord/raid-modal був відсутній у списку внутрішніх bearer-маршрутів src/proxy.ts. Запит бота з Host dashboard:3000 блокувався ще до обробника з HTTP 421. Попередній HTTP-тест бота використовував сервер, який одразу повертав модалку, тому не перевіряв цей proxy.

Дефект відтворено на коді proxy з 3.8.88: HTTP 421. Після виправлення той самий внутрішній запит доходить до route handler. Додано перевірку справжнього production proxy, bearer-авторизації, Ed25519-підпису та маршруту підготовки форми. Невірний токен, підроблений підпис, публічне повідомлення, інший сервер і невідомий Host залишаються заблокованими.

Старі повні модалки залишаються сумісними для вже опублікованих кнопок. Нове меню більше не створює таких кнопок.

- Повний npm run build:ci — успішно, включно з TypeScript, CSS/UI-аудитами та production-збіркою Next.js 16.3.5.
- Сценарії запису — 29/29: персональні та ручні записи, ревізії й власник чернетки, зміна класу, збереження відмови від нагадувань, реєстрація майбутнього акаунта, конкурентні підтвердження та сумісність попередніх модалок.
- Внутрішні маршрути через production proxy — 30/30, включно з 8 сценаріями модалки.
- Тести бота — 55/55.
- Результати: DISCORD_SIGNUP_MENU_RESTORED_VALIDATION_2026-10-15.json.
