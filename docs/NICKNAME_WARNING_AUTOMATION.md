# Discord nickname warning automation

Система перевіряє `member.nick` учасників Discord за глобальним шаблоном гільдії.

Вона **не змінює нік, ролі чи доступи автоматично**. Для некоректного ніку:

1. повторно читає учасника з Discord перед дією;
2. якщо Discord повертає порожній знімок (учасник вийшов із сервера) — прибирає
   його з черги й нічого не надсилає;
3. перевіряє cooldown для тієї самої помилки;
4. намагається надіслати приватне повідомлення (DM);
5. якщо Discord прямо відповідає, що DM до цього користувача заборонені
   (403 / 50007) — тегує учасника у налаштованому fallback-каналі;
6. будь-яку іншу помилку доставки (429, таймаут, 5xx) вважає тимчасовою: запуск
   позначає її як `failed`, публічного тегу немає, перевірку відкладено на годину;
7. записує результат у системний журнал і стан автоматизації.

Повідомлення містить поточний нік, шаблон, приклад, рекомендований нік із профілю (якщо його можна побудувати) та посилання на `/profile`.

Автоматичний scheduler викликається VPS cron кожні 15 хвилин. Глобального
інтервалу немає — на кожному тіку виконується priority-прохід, а відбір іде
per-member через збережений `nextCheckAt`: некоректні ніки переперевіряються
кожні `nicknameInvalidRecheckHours`, коректні — кожні `nicknameValidRecheckHours`.
Повний sweep (перебудова черги без розсилки) запускається лише тоді, коли минув
інтервал `nicknameValidRecheckHours` або змінився шаблон. Автоматична розсилка за
замовчуванням вимкнена й вмикається у **Керування → Discord → Глобальні правила
Discord**.

Основні події журналу:

- `discord.nickname_warning.sent`
- `discord.nickname_warning.manual`
- `discord.nickname_warning.auto_started`
- `discord.nickname_warning.auto_completed`
- `discord.nickname_warning.auto_failed`

## Role-gated перевірка новоприбулих

Панель може відкладати перевірку серверного ніку нового Discord-учасника до моменту, коли він отримає вибрану trigger-роль.

- Після ввімкнення або зміни trigger-ролі перший scan створює baseline поточних учасників. Вони не вважаються новоприбулими.
- Новий учасник без ролі записується у `discordNicknameNewcomerGateMembers` зі станом `waiting_role` і виключається з full/manual nickname sweep.
- Коли роль зʼявляється, учасник переходить у `qualified`, нік перевіряється одразу.
- Невалідний нік записується у `discordNicknameWarningMembers` зі `checkStatus=invalid`, `eligibilitySource=newcomer_role` і одразу стає due для priority scheduler.
- Валідний нік записується як `valid` та переходить у рідкий цикл повторної перевірки.
- Видача trigger-ролі через rules onboarding запускає класифікацію одразу; вручну видані ролі підхоплюються найближчим cron scan.
- Система не змінює ролі або ніки автоматично; вона лише класифікує та використовує існуючий warning flow.
