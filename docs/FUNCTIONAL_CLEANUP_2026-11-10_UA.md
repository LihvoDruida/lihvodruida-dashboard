# Dashboard 3.19.0 — видалення застарілого функціоналу

Очищено вихідний комплект Dashboard/Bot. Відеофон збережено повністю.

## Видалено

| Функція | Що прибрано | Чинна заміна |
|---|---|---|
| Одноразовий імпорт статей зі статичного сайту | `import/legacy-site/`, SQL/Markdown-джерела, `import-public-content.mjs`, npm-команда `import:public-content`, COPY з Dockerfile, пряма npm-залежність `yaml` | Редактор `/content`, PostgreSQL `siteArticles`, API контенту й завантаження зображень |
| Старі адреси керування | `/admin`, `/admin/[...path]`, `/api/admin/[...path]`, старий дозволений return-path | `/dashboard` і `/api/dashboard`; оновити старі закладки/зовнішні посилання |
| Заглушки GitHub-входу | `/api/auth/github/start`, `/api/auth/github/callback`, повідомлення `discord_only`, браузерний CSP-дозвіл `api.github.com` | Чинний Discord OAuth; налаштовуваний аварійний вхід власника збережений |
| Старий статичний експорт складу | `dashboard/scripts/update_guild.py`, який записував `_data/guild.yml` та `_data/professions.yml` і не викликався поточним проєктом | `/api/guild/sync`, чинне сховище складу та public bridge |
| Окрема дубльована кнопка видалення пулу | `RaidPollDeleteButton.tsx`; її браузерні сценарії переведено на активний `RaidPollActions` | Чинна кнопка «Видалити», bulk-видалення, перевірка відповіді й підтвердження користувача |

Прибрано також невикористані CSS-селектори видалених UI-компонентів, без зміни чинних класів.

Це видалення функцій і шляхів сумісності, а не лише очищення кешу чи документації.
Перенаправлення старих URL картинок рейдів залишені: вони зберігають доступність уже опублікованих зображень.

## Дані й інтеграції

Статті, заявки, профілі, рейди, пули та медіафайли робочої БД не очищалися. Вилучено можливість одноразового імпорту; успішність давнього імпорту не підтверджена робочою БД.
Збережено Discord, Battle.net, Raider.IO, форми заявок, редактор контенту, права доступу, автоматизації та відеофон.
Історичне значення `provider: github` у записах профілів/контрактах і маскування GitHub-токенів у журналах не є працюючим GitHub OAuth; вони не видаляють і не змінюють старі дані.
Історичне поле `github` у відповіді moderation збережене для контрактної сумісності; чинний `applicationsStore.ts` зберігає заявки у PostgreSQL, запитів GitHub не виконує.

## Оновлення

Застосувати код у новому каталозі зі збереженням робочих env. При накладанні поверх старого дерева фізично прибрати файли зі списку `REMOVED_FUNCTIONAL_FILES.txt`; просте розпакування ZIP цього не робить.
Повний список видалень від початкового завантаження — `REMOVED_MEDIA_FILES.txt`. Він не містить відновлених фонових відео.
Перебудувати Dashboard звичайним порядком. Оновити старі зовнішні адреси `/admin` на `/dashboard`; колишні GitHub OAuth URL більше не підтримуються.
SQL для очищення старих записів стрімерів залишається окремою командою за `MEDIA_REMOVAL_2026-11-10_UA.md` і не зачіпає дані поточного очищення.

Фактичні результати перевірок — `VALIDATION_FUNCTIONAL_CLEANUP_2026-11-10.md`.
Окремий публічний Site, VPS та робоча БД не входили в цей етап.
