# Авторизація за наданим шаблоном — 15.10.2026

Dashboard **3.8.100**, bot **3.6.9**, contract **1.1.1**.

Екран `/login` отримав оформлення за прикріпленим MHTML «3IRD UA — українська гільдія WoW: Forever». Використано його пейзаж, темно-синю основу `#0c1734`, золото `#d8b25e`, темну картку з тонкою рамкою та червону кнопку із золотим контуром. Назва й емблема залишаються динамічними даними Mistblossom; чужі назва, навігація та розділи не переносилися. Заголовки використовують чинний локальний шрифт Philosopher, а не відсутні у MHTML файли Forum/Alegreya.

## Зміни

- Одна центрована картка авторизації без меню, юридичної навігації, загального футера, службових SSO/Role Sync-плашок і відступу під верхню панель.
- Локальний AVIF-пейзаж 268 560 байтів перенесено без зміни байтів із MHTML у `public/assets/img/auth/forever-landscape.avif`. Його вихідне посилання в шаблоні — Blizzard content CDN, `Cinematic_Trailer.jpg`; браузер використовує тільки локальну копію. Відео, iframe та скрипти шаблону не додавалися.
- На мобільному є відступи safe-area, вузька картка, кнопка не менше 64 px, перенесення довгих повідомлень і вертикальна резервна форма. На низькому екрані сторінка прокручується до кнопки; fixed-висоти й обрізання форми немає. Парольне поле має шрифт 16 px.
- Авторизаційні селектори `login-content` та `login-guild-name` ізольовані від загальних суфіксних стилів hero/eyebrow, які змінювали геометрію та додавали плашку. CSS решти сторінок не перетематизовано.
- Starfield не ініціалізується при початковому завантаженні login. Екран має статичний пейзаж і підтримує reduced motion.

Аварійний вхід власника лишається умовним: потрібен налаштований ключ і дозвіл чинної auth policy. Це спосіб авторизації, а не навігація. Серверна логіка login до JSX, API авторизації, перевірка доступу, обробка `next`, примусова зміна акаунта, стани виходу й помилок збережені. Юридичні сторінки лишаються доступними за своїми URL, але посилань на них на login немає.

## Перевірка

- `check:login` — **21/21** контракт оформлення, брендингу та чинної авторизації.
- Наявний `check:auth-lifecycle` — **13** регресійних сценаріїв у CI.
- `check:login-browser` — **17/17** на реальному production standalone з копіюванням public/static як у Docker та контрольованим локальним reverse proxy. Перевірено дев’ять ширин 320–1920 px, горизонтальний 667×320, довгі помилки, відсутність видимих меню/футера, keyboard activation, safe return URL, logout, reduced motion, policy-gated аварійну форму та відсутній OAuth config. Runtime-помилок і зовнішніх медіазапитів немає.
- Desktop 1440×1000 та mobile 390×844 візуально оглянуто після фінального виправлення класів. Внутрішні screenshots не включені в реліз.
- Повний `build:ci` та ESLint пройшли. Після фінального перейменування класу назви гільдії додатково пройшли TypeScript, production build, audit:styles, ESLint змінених файлів, browser 17/17 та standalone **6/6**.

Browser-suite є окремим скриптом, потребує зовнішніх Playwright і Chromium. `MISTBLOSSOM_QA_MODULES` задає шлях модулів, `MISTBLOSSOM_QA_CHROMIUM` — executable, `MISTBLOSSOM_QA_OUTPUT` — каталог результатів. Нових production-залежностей немає. Машинні результати: [LOGIN_TEMPLATE_VALIDATION_2026-10-15.json](LOGIN_TEMPLATE_VALIDATION_2026-10-15.json).

Реальний OAuth-перехід у Discord та відправлення аварійного ключа не виконувалися; активацію кнопки перехоплено на локальному start-маршруті. Перевірка мобільного — у Chromium viewport, без фізичного Android/iOS. На VPS цей пакет не розгорнуто.

Це окреме оформлення за запитом користувача. Наступний пункт дорожньої карти **R7.7: налаштування журналу та Security mirror** лишається відкритим; приймання R6 на живих PostgreSQL/Discord не перепозначено завершеним.
